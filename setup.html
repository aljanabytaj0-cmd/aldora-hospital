تهيئة النظام من المتصفح

إعداد مجاني باستخدام GitHub وFirebase فقط. لا تثبيت برامج، ولا أوامر، ولا مفتاح إداري.

تُعالج البيانات داخل متصفحك ولا تُرسلها هذه الصفحة إلى أي خادم. لا تضع هنا كلمة مرور أو مفتاح حساب خدمة.

قبل تجهيز الملف

  1. في Firebase فعّل Authentication → Sign-in method → Email/Password.
  2. من Authentication → Users → Add user أنشئ البريد dev@users.aldora.invalid وكلمة مرور خاصة قوية من 6 أحرف على الأقل وفق سياسة Firebase. إذا كان موجودًا استخدم الحساب الحالي. انسخ UID الخاص به.
  3. أوقف الإدخال أثناء النقل. احفظ قواعد القاعدة السابقة ثم انشر قواعد الصيانة التالية في Realtime Database → Rules:
{"rules":{".read":false,".write":false}}

بعد إيقاف الإدخال، من Realtime Database → Data اختر جذر القاعدة ثم قائمة ⋮ → Export JSON. احتفظ بهذا الملف الأصلي نسخة احتياطية. لا تختَر قسمًا منفردًا.

ملف البيانات جاهز

يحتفظ الملف بالمسارات الأصلية، ويضيف بيانات النسخة الجديدة وملف صلاحيات حساب المطور. لا يحتوي كلمة مرور الحساب ولا يغيّر حسابات Authentication.

الاستيراد إلى جذر Firebase يستبدل محتوى الجذر بهذا الملف. استخدمه مباشرة بعد تصدير البيانات مع بقاء الإدخال متوقفًا، حتى لا تفقد تغييرات أُدخلت بعد التصدير. لا ترفع ملف البيانات إلى GitHub.

تنزيل ملف Firebase الجاهز

أكمل التفعيل

  1. في Realtime Database → Data اختر جذر القاعدة ثم ⋮ → Import JSON، واختر الملف الجديد aldora-firebase-ready.json.
  2. افتح ملف database.rules.json المرفق بالمشروع، وانسخ محتواه كاملًا إلى Realtime Database → Rules ثم Publish. هذه القواعد تستبدل قواعد الصيانة.
  3. افتح صفحة النظام وسجّل الدخول باسم dev وكلمة المرور التي اخترتها في Authentication. من صفحة الحسابات أنشئ المدير المالي والمستخدمين وامنح صلاحياتهم.
  4. جرّب طلب تعيين واعتماده والجرس والتقرير المالي، وتحقق من حدود حساب عادي قبل استئناف العمل.

الصفحة لا تنفّذ أي تغيير في Firebase بنفسها؛ أنت تستورد الملف وتنشر القواعد من Console. النطاق المعتمد وخطة Spark وإعداد GitHub Pages تبقى كما هي.
